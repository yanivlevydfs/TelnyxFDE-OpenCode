When the caller saves a deal, the save_deal tool finds the caller through the KV session map and calls saveDeal on that caller's actor, with the config passed in. The actor writes the itinerary HTML to a fixed slot key (one per caller, bucket capped at 5 objects, one token reused per caller), stores a pending reminder, sets an alarm, and sends an audit event to a singleton AuditLog actor. Later the alarm fires inside the same actor and sends the follow-up SMS through the TELNYX binding. One alarm per actor, so a newer save replaces the reminder. Alarms are delivered at least once, so alarm() always catches its own errors and logs them.
