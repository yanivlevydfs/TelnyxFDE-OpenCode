3 / 18

At call start the workflow fires the webhook once, which reads flags from KV and records the call on the caller's actor. Mid-conversation, the prompt nodes call the MCP server, which reads the KV cache, calls flytlv, and reaches the same caller actor directly through the shared SESSIONS binding. The Python webhook cannot bind actors, so it uses the HTTP facade; the TypeScript MCP server skips that hop. The actor writes the itinerary page to Cloud Storage.
