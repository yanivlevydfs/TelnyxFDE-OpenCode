I chose expression edges for deterministic facts so a degraded backend never depends on the model noticing it, at the cost of less flexible routing. The actor wins for read-modify-write and KV wins for read-mostly caches and flags; MetricsCounter would shard by hour if throughput grows. The one-alarm-per-actor limit means a newer save replaces the reminder, so today there is one reminder per caller, not per deal. Next I would link the human transfer number, add a flight-status branch, and move reminders to a CronTick actor for per-deal scheduling.
