Two pipelines. Code: OpenCode with Telnyx GLM-5.2 writes the code against the acceptance tests; once they pass it is pushed, and GitHub Actions ships each changed service with telnyx-edge v0.5.10 from Linux, because the Windows CLI zipped paths with backslashes. Assistant: provision.py uses the Telnyx Python SDK to store the MCP key as an integration secret, register the MCP server and the hangup tool, create or update the assistant with its workflow, webhook URL and model, and link the phone number. Nothing is hardcoded; every value comes from the environment. After deploy, scripts/ops/live_check.py runs 23 checks (incl. itinerary link 200 and fake-token 404) and scripts/ops/workflow_paths.py runs 15/15; storage_check.py lists the bucket to verify the 5-object cap.
