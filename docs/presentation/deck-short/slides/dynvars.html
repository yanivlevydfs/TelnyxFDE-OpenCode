The webhook overrides the assistant's default variables at call start. The response shape is {"dynamic_variables": {caller_known, call_count, saved_count, last_saved_deal, backend_degraded, flag_deals_enabled, flag_sms_enabled, flag_promo}} — strings only. Signature verification happens first: client.webhooks.unwrap(body, headers) BEFORE json.loads — bad signature → 401, bad JSON → 400, so an unsigned body never reaches parsing. _fetch_context runs _flags(kv) and actor.call(entity, "recordCall") in parallel under WEBHOOK_BUDGET_MS=2500, below the assistant's WEBHOOK_TIMEOUT_MS=8000. On any actor or KV failure, safe defaults (backend_degraded="true", caller_known=false, call_count=0) route the call to a scripted degraded_notice instead of reading raw placeholders on air. The session KV write runs after the response so it never blocks.
